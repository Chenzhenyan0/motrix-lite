Important correction for Motrix Lite
------------------------------------
aria2 is licensed under the GNU GPL version 2 **or later** (all 942 source files
carry "either version 2 of the License, or (at your option) any later version";
see native/licenses/aria2-COPYING, which is the unmodified GPLv2 text and contains
NO OpenSSL exception). The GPL linking exception lives in the separate root-level
file LICENSE.OpenSSL: individual aria2 source files state that the OpenSSL linking
permission is granted by reference to that file.

However, the OpenSSL library actually statically linked into the packaged
`aria2c-arm64-v8a` / `libaria2c.so` binary is **OpenSSL 3.0.0**, not OpenSSL 1.1.1.
This was verified from the git tree of devgianlu/aria2-android v1.37.0, which pins
the `openssl` submodule at commit 89cd17a031e022211684eb7eb41190cf1910f9fa whose
VERSION.dat reads MAJOR=3 / MINOR=0 / PATCH=0 (released 2021-09-07), and from
OpenSSL 3 provider API symbols embedded in the binary (OSSL_PROVIDER_load,
OSSL_LIB_CTX_*, EVP_MD_fetch). See native/licenses/DEPENDENCY-VERSIONS.md.

Consequences:
- OpenSSL 3.0.0 is licensed under the **Apache License 2.0**, not under the old
  OpenSSL + SSLeay dual license reproduced inside LICENSE.OpenSSL. The exception
  text below grants linking permission only for OpenSSL versions "having a license
  identical to that listed in this file", so it does not literally cover 3.0.0.
- This is not a blocker for redistribution: aria2 is GPL-2.0-or-later and Motrix
  Lite is distributed as GPLv3; GPLv3 is compatible with Apache-2.0, so the combined
  work can be distributed under GPLv3.
- Obligations: ship the Apache-2.0 license text and the OpenSSL copyright notice
  (both stored in native/licenses/OpenSSL-3.0.0-*.txt), together with the tree of
  corresponding sources. Retain this legacy exception file for reference because
  aria2's own source headers reference it.

of source files in this program which reference this file.
