# 已知问题与限制（KNOWN ISSUES）

本文列出 Motrix Lite 1.1.0 已知的功能缺失、限制与缺陷。**"已知限制"不等于"缺陷"**：部分条目是当前产品范围或 Android 平台的客观约束，已在 UI 或文档中明示。

- 当前版本：1.1.0（versionCode 2）
- 验证环境：Windows 构建（`:app:assembleDebug` + `:app:assembleRelease`，均含两个原生内核，release 经 R8 + 演示签名）+ 32 个 JVM 单元测试（9 个测试类）；**无 Android 真机/模拟器**，故未做真机验收
- 状态说明：`未修复` / `产品范围` / `平台限制` / `待验证`

## KI-01 不支持 BT / 磁力链接

| 项 | 内容 |
| --- | --- |
| 现象 | 输入 `magnet:?xt=...` 或 `.torrent` 链接时，应用提示"当前版本仅支持 HTTP/HTTPS 直链下载；磁力链接与 BT 种子暂不支持"，不会创建任务。 |
| 原因 | 下载内核为 HTTP Range 分段实现，未实现 BitTorrent 协议（bencode、tracker、DHT、peer wire、piece 校验）。BT 还需要 UDP/TCP 监听端口，与 Android 后台限制、省电策略、运营商网络环境冲突明显。 |
| 影响 | 无法下载 BT 资源；与桌面版 Motrix 的能力差距主要在此。即使切换到 Gopeed/aria2 引擎，当前任务创建与 UI 也只支持 HTTP/HTTPS 直链，不会自动获得 BT 能力。 |
| 当前规避 | 使用支持 BT 的客户端下载后再传输；或等待后续版本把 Gopeed/aria2 的 P2P 能力接入任务创建流程。 |
| 后续计划 | Gopeed/aria2 内核已具备部分协议能力，但需新增 P2P 任务参数、tracker/DHT 配置、端口映射与 UI；Android 后台限制仍是主要障碍。当前版本未实现。 |

## KI-02 不支持 Cookie / Referer / 登录鉴权

| 项 | 内容 |
| --- | --- |
| 现象 | 需要登录、防盗链或临时签名的链接会失败，常见提示："服务器拒绝访问（HTTP 403），链接可能已过期或需要 Referer/Cookie"、"需要登录或授权（HTTP 401）"。 |
| 原因 | 请求只携带固定的 `User-Agent`、`Accept`、`Range`、`If-Range`（见 `engine/TaskDownloader.kt`），没有 Cookie 容器、没有 Referer 设置、没有 Authorization 输入。 |
| 影响 | 网盘直链、付费课程、部分 CDN 防盗链资源无法下载。 |
| 当前规避 | 在浏览器中取得可直接访问的直链（含必要签名参数），尽快下载；签名通常有时效。 |
| 后续计划 | 增加"高级请求头"输入（Cookie / Referer / Authorization），但需注意：<br>① 凭据不要明文写入 `tasks.json`；<br>② 需要"仅对特定域名发送"的白名单机制；<br>③ 会影响断点续传的 `ETag`/`If-Range` 语义。 |

## KI-03 服务器不支持 Range 时只能整文件重下

| 项 | 内容 |
| --- | --- |
| 现象 | 任务详情显示"服务器不支持 Range（单连接）"；暂停后继续可能从 0 开始；下载中被中断则丢失已下载部分。 |
| 原因 | HTTP/1.1 的断点续传依赖 `Range` 请求与 `206 Partial Content`。若服务器对带 `Range` 的请求仍返回 `200` + 完整内容，客户端无法安全地只取剩余部分（`TaskDownloader` 会清空 staging 并从 0 写入，见 `TaskDownloader.kt`）。 |
| 影响 | 大文件在弱网下体验差；无法多连接加速。 |
| 当前规避 | 尽量选择支持 Range 的源；解析链接时会提前显示"断点续传：支持/不支持"。 |
| 后续计划 | 可在单连接模式下实现"已下载字节丢弃 + 服务端 Range 探测重试"，但无法突破协议限制。 |

## KI-04 发布阶段需约 2 倍文件大小的临时空间

| 项 | 内容 |
| --- | --- |
| 现象 | 下载 2 GB 文件时，磁盘峰值占用约为 4 GB（staging 2 GB + 目标文件 2 GB）；空间不足时任务在「正在保存」阶段失败："保存文件失败：..."。 |
| 原因 | 先写入应用专属目录的 staging 文件（支持随机写以做多段下载），完成后**复制**到 `Download/MotrixLite` 或 SAF 目录，复制完成后才删除 staging（`storage/DestinationPublisher.kt` + `engine/DownloadCoordinator.kt`）。 |
| 影响 | 大文件需要预留至少 2.2 倍空间；空间不足时下载白费。 |
| 当前规避 | 下载前确认剩余空间 ≥ 文件大小 × 2.5；优先用 `--size-mb` 较小的测试文件。 |
| 后续计划 | 可选"直接写入目标位置"模式（牺牲多段能力），或在发布前预检可用空间并提前失败。当前**未实现空间预检**。 |

## KI-05 SAF 目录授权可能被系统回收

| 项 | 内容 |
| --- | --- |
| 现象 | 之前选择的自定义文件夹突然不可写，保存失败："无法访问所选保存文件夹，请重新选择" 或 "所选保存文件夹不可写"。 |
| 原因 | SAF 的持久化 URI 授权可能因为用户清理、系统升级、文件提供方（如某些网盘/文件管理器）变更、应用被强制停止后权限失效等原因被回收。应用只在选择时 `takePersistableUriPermission`，无法阻止系统回收。 |
| 影响 | SAF 模式下的保存可能失败；任务停留在「下载失败」，但 staging 数据可能仍在（可重试）。 |
| 当前规避 | 在任务详情页与设置页都有提示；失败后到设置中重新选择同一目录即可（已下载的 staging 会保留，重试时无需重下）。 |
| 后续计划 | 保存失败时自动回退到 MediaStore；提供"重新授权"引导弹窗。 |

## KI-06 未知大小文件与大文件进度不精确

| 项 | 内容 |
| --- | --- |
| 现象 | 服务器不返回 `Content-Length` / `Content-Range` 时，进度条为不确定态、百分比显示 0、剩余时间显示"计算中"；大文件下载中百分比会随速度抖动。 |
| 原因 | 进度百分比基于 `downloadedBytes / totalBytes`；`totalBytes = -1` 时无法计算比例（`Models.kt`）。速度采用滑动平均（`SpeedMeter`，0.6/0.4 加权），天然有滞后。 |
| 影响 | 体验层面，不影响正确性。 |
| 当前规避 | 通知与详情页会显示"正在获取大小"/"计算中"。 |
| 后续计划 | 可在未知大小时显示已下载字节数与连接数，或使用 chunked 传输的估算。 |

## KI-07 Android 15 前台服务 6 小时 / 24 小时限制

| 项 | 内容 |
| --- | --- |
| 现象 | Android 15 设备上，`dataSync` 类型前台服务累计运行超过 6 小时（24 小时窗口内）后，系统回调 `onTimeout(startId, fgsType)`，应用暂停所有任务并提示重新打开应用。 |
| 原因 | Android 15 对 `dataSync` 与 `mediaProcessing` 类型前台服务引入超时限制（24 小时内累计 6 小时）。这是系统策略，应用无法绕过。 |
| 影响 | 超长下载（如数百 GB、低速网络）需要用户重新打开应用才能继续；无法做到"完全无人值守"。 |
| 当前规避 | 应用已重写 `onTimeout(startId, fgsType)`，触发时**优雅暂停**（保存进度、停止前台、释放 WakeLock），不崩溃；用户重新打开应用后可继续。 |
| 后续计划 | 可考虑任务分片唤醒（例如依赖 `WorkManager` 断点续跑），但受系统配额限制，收益有限。 |

## KI-08 HyperOS 激进后台清理仍可能中断下载

| 项 | 内容 |
| --- | --- |
| 现象 | 在小米/红米 HyperOS 设备上，即使应用已启动前台服务，息屏或长时间后台后下载仍可能停止；重新打开应用后任务显示「已暂停」或进度停滞。 |
| 原因 | MIUI/HyperOS 的省电策略、自启动管理、后台限制是厂商定制行为，可能比 AOSP 更激进地冻结或杀死进程，且没有公开 API 供应用查询或申请豁免。`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` 只能覆盖 AOSP 的 Doze，不能完全覆盖厂商策略。 |
| 影响 | 后台下载稳定性依赖用户手动配置白名单。 |
| 当前规避 | 应用内提供引导（见 README 第九节）：<br>1. 电池优化设为"不限制"；<br>2. 允许"自启动"、省电策略设为"无限制"；<br>3. 多任务卡片下拉锁定；<br>4. 允许通知。 |
| 后续计划 | 无法通过代码根治；可考虑接入厂商推送/长连接（不适用于纯下载场景）。**请勿在未配置白名单的设备上做长时下载验收并据此判定失败。** |

## KI-09 无文件校验和验证

| 项 | 内容 |
| --- | --- |
| 现象 | 下载完成后只校验"分段完整性 + 文件长度"，不校验 SHA-256/MD5；服务器内容被中间人替换或源文件本身损坏时无法发现。 |
| 原因 | 当前 `finalizeTask()` 仅做长度与分段求和校验（`TaskDownloader.kt`），未实现哈希计算；HTTP 响应通常也不提供官方校验值。 |
| 影响 | 无法保证内容与发布方一致（尤其是 HTTP 明文下载）。 |
| 当前规避 | 对重要文件，下载后自行比对官方公布的哈希（`adb shell sha256sum` 或拉回本地计算）。 |
| 后续计划 | 在任务中增加可选 `expectedHash` 字段，下载完成后计算并比对；或在详情页提供"复制 SHA-256"能力。 |

## KI-10 无开机自启

| 项 | 内容 |
| --- | --- |
| 现象 | 设备重启后，应用不会自动恢复未完成的下载；需要用户手动打开应用。 |
| 原因 | ① 未声明 `RECEIVE_BOOT_COMPLETED`，也没有 `BOOT_COMPLETED` 接收器；<br>② 即使声明，**Android 15 起不允许应用从 `BOOT_COMPLETED` 广播启动 `dataSync` 类型前台服务**，该路径本身不可行。 |
| 影响 | 重启后需要用户介入一次。 |
| 当前规避 | 打开应用即自动恢复（`MainViewModel.init` 中根据 `autoResumeUnfinished` 拉起服务）。 |
| 后续计划 | 无可靠方案；可考虑 `WorkManager` 的延迟任务做"打开应用前的准备"，但仍需用户打开应用才能进入前台服务。 |

## KI-11 仅一条聚合进度通知，无每任务独立通知

| 项 | 内容 |
| --- | --- |
| 现象 | 通知栏只有一条 "Motrix Lite 正在下载 N 个任务" 的聚合通知；无法在通知栏单独暂停某个任务。 |
| 原因 | `NotificationHelper` 只维护固定 ID `1001` 的前台通知；完成/失败提醒才是每任务一条（`resultId`）。聚合设计是为了避免大量任务时通知刷屏与系统限流。 |
| 影响 | 多任务场景下操作粒度粗；只能"暂停全部/继续全部"。 |
| 当前规避 | 在应用内对单任务操作。 |
| 后续计划 | 按任务分配通知 ID，并限制同时展示的数量（如最多 3 条 + 聚合汇总）。 |

## KI-13 允许 HTTP 明文下载

| 项 | 内容 |
| --- | --- |
| 现象 | 应用接受 `http://` 链接（Manifest 中 `android:usesCleartextTraffic="true"`），流量未加密。 |
| 原因 | 为兼容大量仍使用 HTTP 的下载源（尤其是局域网/自建服务/老站点），默认放开明文流量。 |
| 影响 | ① 内容可被中间人篡改；② 下载 URL 与文件内容对同一网络中的攻击者可见；③ 无法防御 DNS 劫持。 |
| 当前规避 | 优先使用 HTTPS 链接；仅对可信源使用 HTTP；知道自己在下载什么。 |
| 后续计划 | 增加"仅允许 HTTPS"开关（默认关闭以保持兼容），或改用 `network_security_config.xml` 按域名放行。 |

## KI-14 任务持久化为单 JSON 全量重写

| 项 | 内容 |
| --- | --- |
| 现象 | 每次状态变化（含 700 ms 防抖后的进度更新）都会把整个任务列表序列化并原子替换 `tasks.json`。 |
| 原因 | 采用"单文件 + 原子替换"的简单模型（`data/TaskStore.kt`），未使用数据库。 |
| 影响 | 任务数量很大（数百）且同时在下载时，序列化开销与 IO 次数会上升；对数十个任务的常见场景无感知。 |
| 当前规避 | 进度回写有 700 ms 防抖；只有状态变更才立即写盘。 |
| 后续计划 | 任务数超过阈值时切换到 Room 或按任务分文件存储。 |

## KI-16 通知权限被拒时无系统通知（仅应用内提示）

| 项 | 内容 |
| --- | --- |
| 现象 | Android 13+ 用户拒绝 `POST_NOTIFICATIONS` 后，前台服务仍能运行，但通知栏看不到进度与快捷操作。 |
| 原因 | 系统行为：没有通知权限时，前台服务通知不会展示；`NotificationHelper` 在未授权时直接跳过 `notify()`。 |
| 影响 | 用户无法从通知栏感知进度或暂停；锁屏后只能回到应用查看。 |
| 当前规避 | 应用内顶部横幅 + 开始下载时的 Snackbar 提示 + 设置页状态说明，并提供"去开启"入口。 |
| 后续计划 | 无（系统限制）。 |

## KI-17 网络切换不会立即中断已建立的连接

| 项 | 内容 |
| --- | --- |
| 现象 | 开启"仅 Wi-Fi"后，如果下载过程中从 Wi-Fi 切到蜂窝，已建立的连接可能继续传输一段时间，直到下一次调度判断才转为「等待 Wi-Fi」。 |
| 原因 | Wi-Fi 策略在 `DownloadCoordinator.kick()` 中判断（`DownloadCoordinator.kt`），只影响**新启动**的任务；正在运行的分段协程不会被主动取消（设计上避免频繁抖动）。 |
| 影响 | 可能产生少量蜂窝流量，与"仅 Wi-Fi"的预期不完全一致。 |
| 当前规避 | 需要严格控制流量时，在切换网络前手动暂停。 |
| 后续计划 | 在网络状态变为非 Wi-Fi 且 `wifiOnly=true` 时，主动 `pauseAll()` 或仅暂停运行中任务。 |

## KI-18 恢复后可能重复建立连接 / 多花少量流量

| 项 | 内容 |
| --- | --- |
| 现象 | 暂停/重启后继续下载时，每个分段的进度以最后一次进度回调（500 ms 粒度）为准，可能重复下载最后不到 1 秒的数据。 |
| 原因 | 进度通过 `AtomicLongArray` 汇总并每 500 ms 上报一次；暂停时未把每个连接当前的精确读取位置落盘（`TaskDownloader.reportProgress`）。 |
| 影响 | 少量重复流量（通常 < 1 MB），文件内容仍然正确（随机写覆盖同一区间）。 |
| 当前规避 | 无需处理，属可接受的取舍。 |
| 后续计划 | 可在取消时把 `progress[]` 强制写回一次（已有 `finally` 中的 `reportProgress(force = true)`），进一步缩小误差。 |

## KI-19 进程被杀可能丢失最近约 1 秒进度

| 项 | 内容 |
| --- | --- |
| 现象 | 强制停止或崩溃后，重启时显示的已下载量可能比实际少一点。 |
| 原因 | 持久化采用 700 ms 防抖（`SAVE_DEBOUNCE_MS`）；被杀时未落盘的最后一次进度会丢失。 |
| 影响 | 重新下载少量数据；不会导致文件损坏（写入是随机覆盖）。 |
| 当前规避 | 正常退出（`onStop` / 服务 `onDestroy`）会 `flush()`。 |
| 后续计划 | 无（这是性能与一致性的合理折中）。 |

## KI-20 Android 8/9 保存位置为应用专属目录

| 项 | 内容 |
| --- | --- |
| 现象 | Android 8/9（API 26–28）上，文件保存在 `Android/data/com.motrixlite.downloader/files/Download/MotrixLite/`，而不是公共的 `Download/MotrixLite`。 |
| 原因 | 分区存储从 Android 10 才引入；在 8/9 上写公共目录需要 `WRITE_EXTERNAL_STORAGE` 运行时权限，本项目明确**不申请任何宽泛存储权限**，因此回退到应用专属外部目录（`DestinationPublisher.publishToAppExternalDir`）。 |
| 影响 | 文件管理器通常能浏览到（可能是隐藏目录），但**卸载应用会删除文件**；其他应用访问受限。 |
| 当前规避 | 下载完成后用应用内"打开文件"或分享；或手动移动到公共目录。 |
| 后续计划 | 可在 8/9 上可选申请 `WRITE_EXTERNAL_STORAGE` 并写入公共 Download（需评估权限最小化原则）。 |

## KI-21 断点续传依赖 staging 文件存活

| 项 | 内容 |
| --- | --- |
| 现象 | 如果 staging 文件被清理（如系统清理、用户手动删除、应用数据被清除），任务继续时会从 0 开始。 |
| 原因 | 续传校验包含"记录有进度但 staging 文件不存在 → 视为文件已变化，清零重下"（`TaskDownloader.kt`）。 |
| 影响 | 极端情况下需要重新下载。 |
| 当前规避 | 不要清理应用数据；系统"深度清理"可能删除 `Android/data` 下的文件。 |
| 后续计划 | 可以在设置中提供"清理未完成任务缓存"的显式入口，避免用户误删。 |

## KI-22 无下载队列编辑 / 排序 / 优先级

| 项 | 内容 |
| --- | --- |
| 现象 | 任务按创建顺序调度，不能拖拽排序、不能设置优先级、不能限制单任务带宽。 |
| 原因 | 当前版本的范围是有序队列 + 全局限速（且全局限速对 Gopeed 任务不生效，见 KI-23）。 |
| 影响 | 大量任务时无法优先下载紧急文件。 |
| 当前规避 | 先暂停不需要的任务，让目标任务获得并发槽位。 |
| 后续计划 | 增加 `priority` 字段与排序 UI；单任务限速需把令牌桶改为按任务分组。 |

## KI-23 Gopeed 不支持全局限速

| 项 | 内容 |
| --- | --- |
| 现象 | 设置页"全局限速"对 `engine=GOPEED` 的任务不生效；Gopeed 任务仍按内核默认/单任务行为下载。内置引擎与 aria2 任务正常限速。 |
| 原因 | Gopeed v1.9.3 的内嵌 REST API 当前不提供"全局限速"接口；Controller 无法把设置下发到内核。`GopeedEngineController` 中以 `lastLimitKb` 变量占位，实际未生效。 |
| 影响 | 用户以为已限速但 Gopeed 任务不受控，可能产生超预期流量。 |
| 当前规避 | 设置页、新建任务弹层与引擎说明中已明确标注"当前 REST API 不支持全局限速"；对流量敏感的场景请使用内置引擎或 aria2。 |
| 后续计划 | 关注 Gopeed 上游是否增加限速 API；或改为按任务限速/客户端限速（需评估精度）。 |

## KI-24 Gopeed 与 App 同进程，Go 崩溃可带崩 App

| 项 | 内容 |
| --- | --- |
| 现象 | 极端情况下（Go panic、OOM、goroutine 异常）可能导致整个 App 崩溃，而不是仅 Gopeed 任务失败。 |
| 原因 | gomobile AAR 把 Go runtime 与 Gopeed 内核链接进 App 进程，没有独立进程/沙箱隔离。 |
| 影响 | 正在运行的内置引擎/aria2 任务也会随进程中断（依赖重启恢复）。 |
| 当前规避 | 固定 Gopeed v1.9.3；限制并发与同时任务数；启动/停止加异常保护；任务完成即停止内嵌服务。无法完全消除风险。 |
| 后续计划 | 关注 gomobile/Gopeed 稳定性；如风险不可接受，可改回内置引擎或评估独立引擎进程方案（需法务与工程量评估）。 |

## KI-25 APK 体积显著增大（原生内核）

| 项 | 内容 |
| --- | --- |
| 现象 | v1.1.0 最终 APK 显著大于 1.0.0（1.41 MB）：debug **67,482,342 B（64.36 MB）**、release **38,559,243 B（36.77 MB）**；aria2 二进制约 69 MB，Gopeed AAR 15,438,987 B。 |
| 原因 | aria2 为静态链接可执行文件，Gopeed AAR 包含 Go runtime 与内核（`libgojni.so` 43,908,776 B）。 |
| 影响 | 安装/更新慢、低端机存储紧张；部分应用商店对 APK 大小有限制。 |
| 当前规避 | 仅打包 arm64-v8a；未放入原生产物时仍可构建轻量版本（引擎显示不可用）；release 已开启 R8/资源裁剪以降低体积。 |
| 后续计划 | 评估按变体（flavor）拆分"轻量版/双内核版"；关注 aria2 精简构建与 AAR 裁剪空间。 |

## KI-26 原生二进制供应链与上游许可状态风险

| 项 | 内容 |
| --- | --- |
| 现象 | aria2 使用 devgianlu/aria2-android 的预编译 arm64 二进制；该仓库**未声明 LICENSE**，二进制可能包含未披露的补丁或额外库。Gopeed AAR 的 Go 模块依赖也未逐项列入主文档。 |
| 原因 | 本环境不具备 Linux/NDK 交叉编译 aria2 的条件；Gopeed AAR 需下载 Go/NDK 工具链构建。 |
| 影响 | 供应链完整性、许可证可追溯性与 GPL 对应源码义务需要额外核对；不能仅凭"来自 GitHub Release"视为安全。 |
| 当前规避 | `native/aria2/fetch.ps1` 固定版本、大小（69,107,592 B）与 SHA-256；本次 aria2 二进制经 24 路 Range 分片下载，最终 SHA-256 `dbfd705d…fc7389a` 与独立下载核对一致；AAR 记录 SHA-256 `aa064e34…dd2d7c`（15,438,987 B）。同时保留 devgianlu 构建文件快照与许可状态说明、Gopeed 构建报告；建议发布前自行重建并记录 SBOM。 |
| 后续计划 | 在 Linux/NDK 环境按 devgianlu 脚本重建 aria2 并公开构建产物哈希；生成 Gopeed `go.sum`/`go version -m` 的完整第三方清单（当前已有关键版本/哈希记录，详见 `.tools/gopeed-build/BUILD_REPORT.md`）。 |

## KI-27 两个原生引擎可同时运行，资源占用增加

| 项 | 内容 |
| --- | --- |
| 现象 | 旧任务使用 aria2/Gopeed 时，新建任务可切换到另一个引擎；两个原生内核可能同时驻留（一个子进程 + 一个同进程 Go 服务）。 |
| 原因 | 任务创建时固定引擎，切换设置不影响旧任务；两个 Controller 独立按需启动。 |
| 影响 | 内存、CPU、耗电、文件句柄增加；低端机或大文件并发时更明显。 |
| 当前规避 | 每个引擎无任务时自动停止；设置页与说明中提示资源开销；建议同一时间只用一个原生引擎。 |
| 后续计划 | 可选"单原生引擎互斥"策略或资源占用提示；需真机测量内存/耗电后再定策略。 |

## KI-28 并发上限不跨引擎统一

| 项 | 内容 |
| --- | --- |
| 现象 | 设置页"同时下载任务数"（1–5）对内置引擎是槽位上限；aria2 与 Gopeed 只在各自内核内按该值调度，三引擎合计的实际活跃任务数可能超过设置值。 |
| 原因 | 内置引擎由 `DownloadCoordinator` 槽位控制；aria2 用 `--max-concurrent-downloads`，Gopeed 用 `maxRunning`，三者没有共享的全局计数。 |
| 影响 | 同时使用多个引擎时，网络/CPU/耗电可能超出用户预期。 |
| 当前规避 | 文档如实说明；需要严格控制并发时建议只使用一个引擎并手动暂停多余任务。 |
| 后续计划 | 如需统一并发，可在 Service 层增加跨引擎任务配额（需处理各引擎内部排队语义差异）。 |

## KI-29 Gopeed 暂停后服务停止/重建，续传行为待验证

| 项 | 内容 |
| --- | --- |
| 现象 | 用户暂停全部 Gopeed 任务后，Controller 因"没有需要运行的任务"调用 `GopeedBridge.stop()` 并清空 `engineTaskId`；恢复时用同一 URL/文件名/任务目录重新创建 Gopeed 任务。是否从已有文件续传，取决于 Gopeed 内核对已存在文件的处理，**当前未经真机验证**。 |
| 原因 | 为了在没有任务时回收 Go 线程与端口，暂停即停止内嵌服务；Gopeed REST 没有"保留暂停任务并稍后 continue"的轻量方案（任务随服务停止而丢失）。 |
| 影响 | 若 Gopeed 恢复时从头下载，暂停/恢复会浪费已下载流量；E2 用例专门验证这一点。 |
| 当前规避 | 对需要频繁暂停/恢复的大文件，建议使用内置引擎或 aria2；文档不宣称 Gopeed 暂停续传一定成立。 |
| 后续计划 | 真机 E2 验证后决定：若确实无法续传，可在暂停时保留服务运行（牺牲资源）或明确 UI 提示。 |

## KI-30 静态依赖供应链：OpenSSL 3.0.0 较旧、libssh2 为 dev 快照

| 项 | 内容 |
| --- | --- |
| 现象 | 随 APK 分发的 aria2 预编译二进制静态链接 **OpenSSL 3.0.0（2021-09 发布，Apache-2.0）**、zlib 1.2.11、c-ares 1.18.1、libexpat 2.4.1、**libssh2 1.9.0_DEV（开发快照）** 与 libc++（NDK r23b）。 |
| 原因 | 二进制来自 devgianlu/aria2-android v1.37.0 的固定 submodule pin；复现构建需按对应 commit 检出，升级会改变二进制哈希。**旧文档曾误写为 OpenSSL 1.1.1 / SSLeay 双许可证，现已根据 submodule pin、`VERSION.dat` 与二进制 OpenSSL 3 API 证据修正。** |
| 影响 | OpenSSL 3.0.0 之后的 3.0.x 修复了多个 CVE（如 CVE-2022-0778、CVE-2022-3786/3602 等）；libssh2 dev 快照非正式发行版，稳定性/安全修复不如正式版可追溯。 |
| 当前规避 | `licenses/DEPENDENCY-VERSIONS.md` 记录精确版本、submodule commit 与证据；`licenses/` 与 APK `assets/licenses/` 提供 OpenSSL 3.0.0 Apache-2.0 全文、OpenSSL 版权声明与各依赖许可证；整包按 GPLv3 分发（GPLv3 与 Apache-2.0 兼容）。 |
| 后续计划 | 正式发布前用更新版本 OpenSSL（以及正式版 libssh2）重新构建 aria2，记录新哈希/SBOM；若继续使用现二进制，应在 Release 说明披露供应链时点与已知风险。 |

## 附：非缺陷的预期行为

以下现象是**设计使然**，验收时不应记为缺陷：

| 现象 | 说明 |
| --- | --- |
| 强制停止应用后任务不会自动继续 | Android 平台限制，需用户重新打开应用 |
| 应用进程被杀后通知消失 | 前台服务随进程结束 |
| 息屏后速度下降 | 省电策略/CPU 降频导致，非应用主动限速 |
| 服务器不支持 Range 时无法多段加速 | 协议限制 |
| 未知大小时进度条为不确定态 | 无 `Content-Length` |
| 发布阶段耗时与文件大小成正比 | 需要完整复制一次 |
| Gopeed 任务不受全局限速影响 | 引擎 REST API 能力限制（KI-23），设置页已标注 |
| 切换引擎后旧任务仍用旧引擎 | 设计如此：任务创建时固定引擎 |
| 未放入原生产物时两个原生引擎显示不可用 | 构建配置可选依赖，非缺陷 |
| 两个原生引擎任务并存时资源占用上升 | 设计允许，已用说明提示（KI-27） |
